Chat Completion APIs

A common interface for sending messages to a language model and receiving responses.

← All AI engineering topics · Updated November 19, 2026

Request and response

An app sends an HTTPS request to a model provider's endpoint, typically with an API key, model name, and conversation messages.

The provider returns an assistant message, usage information, or a tool-call request. Your app handles the result and updates the interface.

Common message roles: system/developer instructions, user requests, assistant replies, and tool results. Exact roles vary by API.

Example request body (simplified)
{
  "model": "example-model",
  "messages": [
    {"role": "user", "content": "Hello"}
  ]
}

Illustrative JSON; endpoint paths and supported fields vary by provider.

Streaming and tool calls

Streaming: response chunks arrive as they are generated, often through server-sent events. The UI can show text immediately.

Tool calling: the model proposes a function name and arguments; your application executes the function and sends its result back for a follow-up response.

MCP: can supply tools to the application; the Chat Completion API handles the conversation with the model.

Production concerns and job relevance

Protect keys on the server, handle rate limits and errors, validate tool arguments, monitor token usage and cost, and avoid losing conversation context.

Interview preparation: backend and AI application roles may ask about HTTP requests, authentication, JSON schemas, streaming, latency, retries, and tool execution.
