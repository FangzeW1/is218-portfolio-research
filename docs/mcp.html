Model Context Protocol (MCP)

MCP connects AI applications to external tools and data through a common protocol.

← All AI engineering topics · Updated November 19, 2026

How MCP works

Host: the AI application. Client: its connection to an MCP server. Server: exposes tools, resources, or reusable prompts.

  1. Client discovers a server's available tools and JSON input schemas.
  2. The model chooses a tool and supplies arguments.
  3. The host validates permissions and invokes it through the client.
  4. The server returns data for the model to interpret.

MCP standardizes integration; it does not replace HTTP or make an API automatically safe.

Example: room item valuation

Upload a photo → identify likely products → call an eBay pricing tool → compare listings → estimate resale value with uncertainty.

An MCP server could wrap the eBay API. The server handles API authentication and requests; the AI handles which tool to use and how to explain results.

Asking prices are not completed-sale prices. Historical sold data depends on the API's access and availability.

When MCP helps

Useful when an agent needs multiple reusable integrations, such as GitHub, databases, or monitoring systems. A direct API call may be simpler for a single service.

Interview preparation: AI agent and integration roles may ask about tool schemas, client/server responsibilities, authorization, prompt injection, and human approval before write actions.

Security checklist

Restrict tool permissions, validate inputs, protect API keys, treat external tool output as untrusted, and require approval for destructive actions.
