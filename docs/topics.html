Retrieval-augmented generation (RAG)

Core idea: retrieve relevant information from an external source, then provide it as context to a language model when generating an answer.

My pipeline: Markdown documents → chunk text → generate embeddings → store vectors → embed the question → retrieve matching chunks → generate a streamed response.

Full IS373 experiment and evaluation notes

Embeddings and vectors

A vector is an ordered list of numbers. An embedding is a learned numerical representation of text (or other data) used to compare related content.

Similarity scores reflect model representations, not guaranteed factual agreement.

Vector retrieval

Finds passages with embeddings close to the query embedding. Useful when the question and source use different wording.

Knowledge graphs

Represent entities as nodes and explicit relationships as edges. Useful for questions about who has access, what depends on what, and how facts connect.

Hybrid and graph-enhanced RAG

Keyword retrieval and vector retrieval can be combined; graphs can add explicit relationships. These are different techniques and can complement one another.

Chunking

Divides documents into retrievable pieces. Chunk size and overlap affect which context the model receives and what it may miss.

Evaluation and source attribution

A relevant retrieved chunk is not proof that an answer is correct. Test answers against source text and distinguish retrieved sources from verified citations.
