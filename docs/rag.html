Retrieval-Augmented Generation (RAG)

RAG searches source material before a language model answers.

← All AI engineering topics · Updated November 19, 2026

The RAG pipeline

Documents → clean and chunk → embed → index → retrieve relevant passages → generate a grounded answer.

Why use it? Answer questions using changing or private documents without retraining the model.

Example: A support bot retrieves the refund policy before answering a customer's question.

Design decisions

Chunking: Split text into passages. Large chunks preserve context; small chunks can improve precision but lose surrounding details.

Embeddings: Numerical representations that help retrieve text with related meaning, even when wording differs.

Retrieval: Keyword search matches terms; vector search matches learned representations. Hybrid search combines them.

Citations: Display the actual source passages or document locations so users can verify answers.

When do knowledge graphs help?

Graphs explicitly store entities and relationships. They help answer questions about dependencies, ownership, or connections that similarity search alone may miss.

Testing and job relevance

Measure whether the right passages are retrieved, whether answers match evidence, and whether the system correctly refuses unsupported claims. Test latency and cost too.

Interview preparation: AI application, search, and backend roles may ask you to explain chunk size, embedding choice, vector vs. keyword search, hallucinations, and how you evaluate retrieval quality.

A high similarity score does not prove factual agreement.
